# Android 15 Edge-to-Edge Audit

**Project:** WAKA POS Android (`ug.waka.pos`)  
**Date:** 19 August 2026  
**Target / compile SDK:** 36 (Android 16)  
**Min SDK:** 24  
**Native shell:** Capacitor 8 (not Flutter, not Cordova UI)  
**Play Console issue:** deprecated edge-to-edge window APIs on Android 15+

---

## Executive summary

WAKA’s own Java/Kotlin code does **not** call:

- `Window.setStatusBarColor()`
- `Window.setNavigationBarColor()`
- `Window.getStatusBarColor()`
- `Window.getNavigationBarColor()`

The Play Console warning is a **static DEX scan** of third-party libraries that still contain those methods for pre–Android 15 compatibility. The same warning is widely reported for Material Components and Ionic’s camera AAR.

**Can the warning be ignored until upstream libraries update?**  
**Yes, for Play publishing.** It is a compatibility notice, not a policy rejection. WAKA already draws edge-to-edge (Capacitor `SystemBars` + `viewport-fit=cover`). The remaining hits cannot be removed without dropping camera/Material or waiting for stable Material 1.14 / Ionic Camera updates.

**Do not publish** a Play release solely to “clear” this warning — it will still appear until upstream bytecode changes.

## 2. Attribution — where the calls come from

### 2.1 Our own code

| File | Finding |
|---|---|
| `android/app/src/main/java/ug/waka/pos/MainActivity.java` | Previously called `WindowCompat.setDecorFitsSystemWindows(window, false)` (wraps deprecated `Window.setDecorFitsSystemWindows` on API 35+). **Does not** set/get bar colors. |
| `WakaMlkitOcrPlugin.java` | OCR only — no window APIs |
| `WakaAppUpdatePlugin.java` | Play In-App Updates only — no window APIs |
| `src/lib/capacitorInit.ts` | Uses Capacitor 8 `SystemBars.setStyle()` (WindowInsetsControllerCompat on native) |

**Not Flutter.** There are no Flutter plugins.

### 2.2 Capacitor / generated code

| Component | Role |
|---|---|
| `@capacitor/android` `SystemBars.java` | **Correct Android 15 path:** `WindowInsetsControllerCompat` for icon appearance and show/hide. CSS `--safe-area-inset-*` injection. No Window color APIs. |
| `android/app/capacitor.build.gradle` | Generated by `cap sync` — plugin module list only |
| `@capacitor/splash-screen` | Immersive splash uses `WindowInsetsController` (API 30+) and `WindowCompat.setDecorFitsSystemWindows`. Legacy pre-R path uses `SYSTEM_UI_FLAG_*` (not the four color APIs). |
| `@capacitor/keyboard` | Defers inset sizing to SystemBars when present |

### 2.3 Ionic Camera library (primary Play-visible app code path)

`@capacitor/camera` depends on:

```gradle
implementation 'io.ionic.libs:ioncamera-android:1.0.x'
implementation "com.google.android.material:material:1.13.0"
```

Bytecode:

- `io.ionic.libs.ioncameralib.view.IONCAMRImageEditorActivity`  
  → `getStatusBarColor()` / `getNavigationBarColor()`  
  Present in **both** `ioncamera-android` **1.0.1** (installed) and **1.0.2** (camera 8.2.2).
- Capacitor camera also ships `CameraBottomSheetDialogFragment`, which pulls Material `BottomSheetDialog`.

This is the “Ionic Camera library” Play is seeing.

### 2.4 Material Components (primary Play Console stack frames)

Typical Play Console frames match Material GitHub [issue #4507](https://github.com/material-components/material-components-android/issues/4507):

- `com.google.android.material.bottomsheet.BottomSheetDialog.onCreate`
- `com.google.android.material.internal.EdgeToEdgeUtils.applyEdgeToEdge`
- `com.google.android.material.sidesheet.SheetDialog`

WAKA does not depend on Material directly. It is **transitive via `@capacitor/camera`**.

Material maintainers: a 1.14.0-alpha fix was **reverted** after regressions. A later fix (`c2051db`) is **only on 1.14 / master**, still not a stable Play-safe release as of this audit. **1.13.0 still triggers the warning.**

### 2.5 AndroidX libraries (always packaged; used for pre-35 compat)

| Library | Version pinned | Classes with color APIs | Why they exist |
|---|---|---|---|
| `androidx.activity:activity` | 1.11.0 | `EdgeToEdgeApi23/26/29` | Official `enableEdgeToEdge()` still paints transparent bars on API &lt; 35 by calling the deprecated setters |
| `androidx.core:core` | 1.17.0 | `WindowCompat` | Backward-compat helpers |
| `androidx.core:core-splashscreen` | 1.2.0 | `SplashScreen$Impl31` | Android 12+ splash restores window bar colors after the system splash |

`androidx.appcompat:appcompat:1.7.1` — **no** matches for these four methods in the cached AAR.

### 2.6 Other scanned artifacts — clean

No matches in: Play In-App Update (`com.google.android.play:app-update`), ML Kit text recognition, Cordova framework, WebKit, CoordinatorLayout, Fragment, AppCompat, GMS artifacts present in the local cache.

### Not applied (not safe)

| Candidate | Reason |
|---|---|
| `com.google.android.material:material:1.14.0-alpha*` | Alpha. Play still reported the warning after 1.14.0-alpha01; Material reverted the first fix. |
| Capacitor Android `8.4.1` → `8.5.0` | Minor platform bump; not required for this audit; risk of SystemBars/WebView behavior change. |

| `core-splashscreen` beyond 1.2.0 | 1.2.0 is current; Impl31 still restores bar colors via the deprecated APIs. |

## 4. WAKA migration (no product UI change)

Recommended Android 15 Activity setup is:

1. `SplashScreen.installSplashScreen(this)`
2. `EdgeToEdge.enable(this)`  (`androidx.activity.EdgeToEdge`)
3. `super.onCreate(...)`
4. Let Capacitor `SystemBars` + CSS `env(safe-area-inset-*)` handle insets

`index.html` already has `viewport-fit=cover`.  
`capacitor.config.ts` already has `plugins.SystemBars.insetsHandling: "css"`.

This replaces `WindowCompat.setDecorFitsSystemWindows(false)` only. Sell / web / Android layouts are unchanged. No Material 3 theme migration (would change look).

## 6. Remaining third-party issues (will still appear in Play Console)

After this change, Play’s static analysis is expected to keep reporting:

1. **Material 1.13.0** — `BottomSheetDialog` / `EdgeToEdgeUtils` / side sheets  
   *Source:* `@capacitor/camera`  
   *Clearance:* stable Material **1.14+** that no longer references the APIs, then bump via `androidxMaterialVersion`.

2. **ioncamera-android 1.0.2** — `IONCAMRImageEditorActivity.getStatusBarColor/getNavigationBarColor`  
   *Source:* Ionic `io.ionic.libs:ioncamera-android`  
   *Clearance:* Ionic must ship a 1.0.3+ that uses `WindowInsetsControllerCompat` only.

3. **androidx.activity EdgeToEdgeApi\*** — `setStatusBarColor` / `setNavigationBarColor` for API &lt; 35  
   *This is Google’s official helper.* Play may still list it. Cannot be removed while supporting minSdk 24.

4. **androidx.core.splashscreen Impl31** — restores bar colors after splash  
   *Clearance:* AndroidX splash-screen library update.

5. **androidx.core WindowCompat** — compat wrappers

## 7. Play Console impact

| Question | Answer |
|---|---|
| Policy / blocking? | **No.** This is the Android 15 “deprecated APIs or parameters for edge-to-edge” **warning**, not a Data safety or permission violation. |
| Runtime on Android 15 (target 36)? | `setStatusBarColor` / `setNavigationBarColor` **have no effect** for the status bar and gesture nav. Edge-to-edge is enforced. WAKA already handles insets in the WebView. |
| User-visible bug if ignored? | Unlikely for the main POS WebView. Camera **bottom sheet / image editor** may still use Material’s internal edge-to-edge helper; that is Ionic Camera, not the sell screen. |
| Will a new AAB without Material camera clear it? | Yes, but that would remove photo capture — not acceptable. |
| When will the warning go away? | When Material 1.14 stable + ioncamera drop the APIs **and** Play rescan; Activity/SplashScreen hits may remain by design. |

**Recommendation:** keep shipping. Treat the warning as **upstream**. Re-check after:

- Material `1.14.0` stable
- `@capacitor/camera` / `ioncamera-android` release notes mentioning edge-to-edge / WindowInsets

Do **not** set `android:windowOptOutEdgeToEdgeEnforcement` — that flag is temporary and will stop working.
